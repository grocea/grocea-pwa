## Observed evidence

- `public/sw.js`: fixed `grocea-pwa-v5-auth-proxy` cache; install precaches root/index/manifest/icons but no emitted JS, CSS or fonts. Assets are filled opportunistically after load. Successful network navigations never replace cached index. Consequently newer network HTML and older offline HTML can diverge; this is a source-supported risk, not an executed reproduction.
- Same file: unconditional `skipWaiting()` and activation `clients.claim()` can replace the controller beneath open application clients. Activation deletes every cache except its own, including unrelated same-origin caches. Generic GET handler caches arbitrary non-navigation responses, including cross-origin GETs; only same-origin `/api` and `/api/` bypass it. `caches.match()` searches all caches, allowing accidental cross-generation matches.
- `src/registerServiceWorker.ts`: production-only registration on window load, with console-only failure. No waiting/update/offline-ready state. `src/main.tsx` calls it after rendering.
- `vite.config.ts`: React Vite build with development `/api` loopback proxy only. `package.json`: `tsc -b && vite build`, Vite preview, deploy through Wrangler; no current precache generation or build version identifier.
- `src/api/client.ts`: production API origin is always empty (same-origin proxy), development can configure `VITE_API_ORIGIN`. `src/worker.ts`: `/api` and `/api/` proxy to `BACKEND_ORIGIN`, other requests use `ASSETS.fetch`. `wrangler.jsonc`: SPA assets and `run_worker_first: ["/api/*"]`. Bare `/api` routing and asset response headers deserve explicit release verification. No custom asset cache headers were found in these inspected deployment files.
- `src/app/persistence.ts`: durable `outbox` is in IndexedDB, separate from CacheStorage; update code must never clear/delete databases or local auth metadata. Existing verification helpers use `grocea:${accountId}` and read queue IDs/payloads.
- `tools/verify-restock-browser.mjs`: already attaches CDP sessions to existing service-worker targets and sets both worker and page offline. Reuse its loopback-only guard, disposable registration and durable queue checks. Existing worker enumeration alone is insufficient if a target restarts after offline emulation; cover subsequently attached workers too.
- Original `docs/next-phase/prompts/T01.md` and `plans/01.md` require multi-build updates, sensitive-cache exclusion, outbox persistence, explicit physical-device pending status, and no pytest/Vitest reinstatement.

## Small implementation contract

Use Vite's existing build pipeline with a small build plugin or Node post-build script; no generic PWA framework. Generate `dist/sw.js` from a dedicated template after final output exists. Inventory emitted application assets (including CSS-referenced fonts), `/index.html` and an explicit public shell allowlist (manifest, app icons, actual runtime public icons). Exclude service-worker script, source maps, documentation, API output and arbitrary public data. Sort canonical paths; hash paths AND file bytes, including worker template bytes, into a deterministic build ID. Embed the ID and exact precache list in the generated worker; identical inputs yield identical ID, changed HTML/assets/worker yield a new one. Do not derive identity solely from package version or Git SHA (uncommitted builds must differ).

Use `grocea-shell-<buildId>`; install must complete the entire precache before succeeding. Fetch canonical public files with HTTP cache revalidation/bypass and reject redirects, non-200 responses or unexpected HTML for JS/CSS/icon/font paths. Failed installation must leave the active build intact. Do not put index under multiple runtime route keys. Store only canonical `/index.html`; deep app routes resolve to it.

For the simplest coherent lifecycle, controlled navigation returns the active worker's precached index, and public assets return only exact matches from that worker's own cache. Check registration updates independently; avoid network-first HTML that can jump ahead of the active worker. Allow no arbitrary runtime cache writes. Same-origin GET and exact allowlist matching are mandatory; unknown paths, query variants, cross-origin URLs, authenticated requests and `/api` paths bypass CacheStorage. Sensitive JSON/export/auth requests cannot become a cached shell response; navigation fallback should be limited to app document requests, not API URLs. Where requests carry explicit authorization, bypass shell cache even for an otherwise matching asset URL.

Avoid unconditional `skipWaiting` and `clients.claim`. A new build waits while old clients are open; old clients keep their complete old cache. Activation occurs after old controlled clients close. An unobtrusive “Update ready — close other Grocea tabs and reopen” message can expose this natural lifecycle without forced reload or queue loss. If an explicit immediate-update action is later desired, it needs a separately verified multi-tab persistence/coordination contract; do not introduce it for this task. First install readiness requires successful complete precache; authenticated offline readiness additionally requires durable successful first sync. `navigator.serviceWorker.ready` alone does not prove first-page control or cached authenticated state. Registration failure and update-install failure should leave useful truthful status.

Activation cleanup deletes only obsolete `grocea-shell-` caches, only after safe natural activation. Never clear IndexedDB/outbox. Handle the legacy fixed Grocea cache as a narrowly named migration target, not a broad prefix that could catch unrelated applications. Natural lifecycle means old clients no longer need the preceding worker cache at activation; verify this with two tabs. CacheStorage eviction remains a browser/storage limitation: no promise of permanent offline availability.

Serving: add explicit `/sw.js` and `/index.html` revalidation/no-cache headers, correct JavaScript MIME for worker, and immutable long-lived headers only for content-hashed assets. Ensure the local production verification server mirrors worker proxy and SPA fallback behavior. Verify actual response headers in local harness; deployment configuration inspection cannot prove hosted behavior. Keep hashed assets available during release transitions; installed caches help existing clients but cannot guarantee a first uncontrolled old HTML document will survive asset deletion.
